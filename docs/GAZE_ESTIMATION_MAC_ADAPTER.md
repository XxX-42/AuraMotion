# Mac-only gaze_estimation debug adapter

The Debug HUD's **GazeEstimation · Mac** toggle starts a separate worker from the sibling `../gaze_estimation` repository. It receives AuraMotion's existing capture frames; it does not open another webcam or generate cursor/keyboard events. The worker executes that project's MediaPipe observation, head-pose and normalized eye-patch pipeline. The HUD displays the image-left and image-right patches. Patches are transmitted in memory, not saved to disk. The toggle is off by default and closes the worker when disabled.

The sibling project's own OpenCV camera entry point requests Linux V4L2 and therefore is not used on macOS. Its pinned MediaPipe 1.0.1 crashed on this machine, so run `./scripts/setup_gaze_estimation_adapter.sh` to install MediaPipe 1.1.1 into an AuraMotion-local override under `build/`, without altering the sibling repository's virtual environment. The existing `gaze_estimation/.venv` and `models/face_landmarker.task` must exist. Launch with `./scripts/dev.sh` so the adapter can find the sibling and script paths; `AURAMOTION_GAZE_ESTIMATION_DIR` can override the repository location.

The adapter does **not** invent CNN weights. It auto-discovers only locally trained `runs/**/pretrained.pt` files with a completed `test_metrics.json`; it rechecks when no model is loaded. An explicit `AURAMOTION_GAZE_ESTIMATION_MODEL` path is also supported. A loaded model produces its upstream geometric prediction, displayed as numeric **未校准预测** values only; it does not replace AuraMotion's gaze estimator or control the cursor. The upstream screen geometry defaults are not measurements of this Mac, and the adapter offers a separate experimental nine-point calibration in the existing calibration window (CNN 角度九点校准). Each target and its corresponding same-frame eye center and normalization rotation produce a target direction; a regularized affine fit maps the CNN angles to these directions. The calibrated ray is transformed back to camera space and intersected with the assumed display plane. The sibling project’s default 340 × 190 mm geometry and 10 mm camera offset are estimates, not measurements of this Mac. The displayed fit error is in-sample, not a held-out accuracy measurement. Off-screen or invalid intersections are not clipped into fake edge predictions. The fitted coefficients are stored locally and restored only when the model and processing signature, camera and format, input mirroring, display and assumed screen geometry match; camera images and raw calibration samples are not saved; green × is the CNN prediction, cyan × belongs to the original AuraMotion estimator. Accuracy is not validated on the user. Switch the toggle off and on to reload a different model, then repeat calibration.

The included `scripts/train_gaze_estimation_mps.py` runs the sibling project's existing MPIIGaze pretraining entry point with MPS when available and a single-process DataLoader; it does not edit that checkout. Dataset and checkpoint data remain in the sibling repo's ignored `data/` and `runs/` directories. MPIIGaze is CC BY-NC-SA 4.0; see the sibling's `data/external/README.md`. A small, short training run is only a preliminary experimental model; its held-out participant metrics and personal calibration are needed before interpreting accuracy.

The separate `gaze` repository's GazeBeamHost is buildable on the Mac, but that SDK requires ARKit face samples from a Face ID iPhone. It cannot acquire equivalent 3D eye rays from the Mac webcam. Per the current Mac-only choice, no iPhone provider is started, and no simulated samples are presented as real gaze.

In Debug, the Mac CNN starts automatically and reuses a compatible saved calibration. A non-interactive cyan-ring/white-cross panel shows the smoothed gaze point on the main display; it does not move the system mouse or accept clicks. It stays wholly inside the main display when a finite ray projects beyond an edge. During temporary tracking loss the last marker remains dimmed; this is visual-only, and unavailable or off-screen gaze cannot select or activate an AX target. It is hidden while calibration is open or when the CNN is switched off. Disable GazeEstimation · Mac to hide it and stop the worker.

The optional main-screen gaze spotlight follows the displayed gaze marker, including semantic target snapping. It uses a 500 pt radius, a 5% white overlay inside and a 20% black overlay outside. The non-interactive, accessibility-ignored panel can be toggled with “眼动遮罩” in the HUD and hides while the gaze marker is suppressed.
